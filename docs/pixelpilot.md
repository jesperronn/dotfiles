# pixelpilot

A Node.js screenshot reviewer. It compares the PNGs in a current screenshot folder against a baseline (by default, the `doc/screenshots` folder at a Git ref), and writes an HTML review page with side-by-side views and a diff mask for each changed image. The page is a single file, but it loads images by relative path, so keep it in place next to the `diffs/` folder and the screenshot folders it references.

## Start

```bash
pixelpilot --help
pixelpilot --baseline v1.2.0
```

Run it from the root of the project being reviewed. The defaults assume that layout:

| Option | Default | Meaning |
| --- | --- | --- |
| `--current-dir` | `tmp/screenshot-output` | Folder with the current PNGs. Every `*.png` here becomes a scenario. |
| `--baseline-dir` | `doc/screenshots` | Folder the baseline PNGs are extracted into (see below). |
| `--baseline` | `HEAD` | Git ref whose `doc/screenshots/*.png` form the baseline. |
| `--output-html` | `tmp/screenshot-review/index.html` | Where the review page is written. Diff images go to `diffs/` beside it. |
| `--manifest` | generated | JSON file that replaces the generated manifest (see below). |

When the review is written in an interactive terminal, pixelpilot waits 5 seconds and offers to open the page: press `o` to open it in the browser, or let the countdown run out. Without a terminal, it only prints the `open <path>` line.

## Typical run

```bash
# Current screenshots are produced by your test suite into tmp/screenshot-output
pixelpilot --baseline v1.2.0 --output-html tmp/screenshot-review/index.html
```

Output on success:

```text
Generating screenshot review page with:
  baseline: v1.2.0
  current-dir: tmp/screenshot-output
  baseline-dir: doc/screenshots
  output-html: tmp/screenshot-review/index.html
Wrote screenshot review page to tmp/screenshot-review/index.html
```

## How the baseline is built

Without `--manifest`, pixelpilot:

1. Checks that `--baseline` resolves with `git cat-file`.
2. Extracts every `doc/screenshots/*.png` at that ref into `--baseline-dir`, flattening the paths to file names.
3. Runs `git describe --long` on the baseline ref and on `HEAD`, and records the results in the manifest.
4. For each PNG in `--current-dir`, builds a diff image in `diffs/` when a baseline PNG of the same name exists. Pixels that differ are opaque white on a transparent background. Identical images produce no diff image, and the page shows the current image in its place.

Matching is by file name only. A current screenshot with no baseline counterpart still appears in the page, without a baseline image.

## Manifest

`--manifest <file.json>` skips steps 1–4 entirely: no Git calls, no extraction, no diffs are generated by pixelpilot. Use it when you already have the baseline and diff data. The file must contain:

```json
{
  "baseline": { "ref": "v1.2.0", "describe": "v1.2.0-0-gabc1234", "generated_at": "2026-10-20T10:00:00.000Z" },
  "current": { "describe": "v1.2.1-3-gdef5678", "generated_at": "2026-10-20T10:00:00.000Z" },
  "scenarios": [
    {
      "file": "home.png",
      "baseline_path": "../../doc/screenshots/home.png",
      "current_path": "../../tmp/screenshot-output/home.png",
      "diff_path": "diffs/home.png"
    }
  ]
}
```

Paths in `scenarios` are relative to the output HTML file.

## Gotchas

- **`--baseline-dir` is an output folder, not an input.** Without a manifest, pixelpilot writes the baseline PNGs from Git into it, overwriting any file with the same name. Point it at a scratch folder, not at a hand-maintained screenshot folder. This happens before `git describe` runs, so it also happens when the run then fails.
- **Refs must have an annotated tag.** `git describe --long` is used for labels, and it fails on a repository with no tags or with only lightweight tags. Create one with `git tag -a v1.2.0 -m v1.2.0`.
- **Only `doc/screenshots` at the ref is read.** A baseline stored elsewhere needs a manifest.
- **Sizes must match for a pixel diff.** If a baseline and current PNG differ in dimensions, pixelpilot does not fail; it writes a placeholder diff that reports both sizes instead.
- Errors go to stderr and exit with status 1.

## Files

- [bin/pixelpilot](../bin/pixelpilot) — launcher; calls the review CLI.
- `bin/lib/pixelpilot/review-cli.js` — argument parsing, baseline extraction, manifest, output.
- `bin/lib/pixelpilot/review-html.js` — renders the self-contained HTML page.
- `bin/lib/pixelpilot/review-page.js` — browser-side script embedded in that page.
- `bin/lib/pixelpilot/image-diff.js` and `diff-artifacts.js` — dependency-free PNG decoding and diff masks.
