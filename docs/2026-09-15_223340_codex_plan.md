# npm-global-audit TTY Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Show responsive, readable package-audit progress in an interactive terminal without changing the existing final-only output when stdout is not a TTY.

**Architecture:** Discover and sort all package specs before starting workers. In a TTY, render one dim `pending` row per package and one transient status row. A coordinator owns terminal drawing and reaps workers as their per-job result file appears; it replaces exactly that package row immediately and updates the status count. Workers never write to stdout.

**Tech Stack:** Bash, npm, ANSI cursor controls, `bin/lib/bash_test.sh`, ShellCheck.

## Global Constraints

- Preserve non-TTY output byte-for-byte: no pending rows, ANSI controls, or progress status when stdout is redirected or piped.
- Keep all npm calls and temporary project isolation unchanged; this is presentation and worker-reaping only.
- Default concurrency remains `max(processor count, 8)`; `--jobs N` remains supported.
- In a TTY, show static dim `pending` per unresolved package, not one spinner per row.
- Show exactly one temporary status row: `Resolving and auditing packages: N/T complete`.
- Once package discovery has completed, do not perform a serial `npm outdated -g --json` request before rendering or starting audit workers.
- The update lookup is a separate progress phase: show `Checking for available updates...` while it is running, then incorporate its data into completed package rows as soon as it is available.
- Replace a package row when that worker completes; do not wait for the oldest worker or for the full batch.
- Remove the temporary status row before printing the existing `Next:` section.
- Do not use a timer-driven spinner. The increasing completed count is the meaningful progress signal.
- Tests must use PATH-shadowed npm stubs and must not access the network or real global npm state.

### Task 3: Add the bounded completion-event loop

**Files:**

- Modify: `bin/npm-global-audit`
- Test: `bin/npm-global-audit.test.sh`

**Interfaces:**

- `start_job INDEX`: starts one worker and records its PID and job directory.
- `reap_completed_jobs`: scans active job directories for atomic `status` files, waits only those PIDs, and returns their indexes.
- `render_tty_pending_rows`: prints every initial aligned pending row and one status row.
- `replace_tty_row INDEX TEXT`: moves from the status row to the indexed row, clears it, writes TEXT, returns to the status row, and redraws status.

- [ ] **Step 1: Build arrays before any worker starts.**

Parse all sorted records into parallel arrays: names, versions, specs, and job directories. Compute width once. This allows every pending row to be printed immediately instead of leaving a blank terminal during package launch.

- [ ] **Step 2: Branch once on `[[ -t 1 ]]`.**

Non-TTY branch: retain final-only output, but start update lookup and package workers without imposing an unnecessary serial dependency. TTY branch: immediately print all `pending` rows, a primary status row `Resolving and auditing packages: 0/T complete`, and a secondary transient phase row `Checking for available updates...`; then start at most `JOBS` workers.

- [ ] **Step 2a: Start update lookup concurrently.**

After global package discovery, start `npm --no-audit outdated -g --json` in one background job and write its stdout to `WORK_DIR/outdated.json`. Do not wait for it before printing pending rows or launching package workers. Parse it only after its output is complete; an unavailable or malformed update response must behave as the current best-effort lookup (no update annotation), never fail an otherwise valid audit.

- [ ] **Step 3: Reap whichever workers complete.**

Loop while packages remain unstarted or active. For every active `JOB_DIR/status` found, `wait PID`, call `render_completed_job`, increment completed count, replace that one row, and start another queued job. If none has completed, sleep for a short configurable interval; tests set that interval to `0`.

- [ ] **Step 4: Use safe terminal coordinates.**

The status row is immediately below the N package rows. To replace zero-based row `i`, move up `T - i` lines, erase (`ESC[2K`), print the completed row without a newline, move down `T - i` lines, and redraw the status row. Do not use cursor controls in non-TTY mode.

- [ ] **Step 5: Finish cleanly.**

When the update lookup completes, remove or replace `Checking for available updates...`; completed rows whose update text was not yet known must be redrawn with their existing vulnerability result plus `— outdated, VERSION available` where applicable. After the final worker and update lookup, erase both transient status rows, print one newline, and then run the unchanged `Next:` rendering. Restore cursor position so the shell prompt follows normal output.

Run: `bin/npm-global-audit.test.sh`.

Expected: the out-of-order test proves row 3 can resolve while rows 1–2 stay pending; non-TTY output remains unchanged.
